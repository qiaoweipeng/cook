# 视觉与交互规范

> 所有颜色、圆角、图标都**必须从下面这套规范里取**。代码实现见 `src/theme.ts` 和 `src/index.css`。

---

## 设计理念

> 这是每天都会打开的**生活类工具**，不是后台管理系统。暖橙唤起食欲，移动端米白降低长时间阅读疲劳，大圆角削弱「表格感」。目标是让人愿意天天用，而不是觉得在点 OA。

## 背景色按端区分

| 端 | 背景色 | 原因 |
|----|--------|------|
| PC | `#FFFFFF` 纯白 | 后台表格多，默认白底；改米白适配成本高 |
| 移动 | `#FAF7F2` 燕麦米白 | 全是卡片流，白卡片浮在米白上层次更好 |

**规则**：看设备，不看页面类型。不要出现「PC 用户端米白、PC 后台纯白」这种按页面分的规则。

### 配套：内容块必须是卡片形态

米白底遇到通栏白条（整宽、无圆角的白色 List）会显得页面被切碎 —— 解法是**每个内容块都有明确边界**。

| 形态 | 允许 | 说明 |
|------|------|------|
| 白卡片（有圆角 + 外边距） | ✅ | 白卡片浮在米白上，参照 iOS 设置页 |
| 通栏白条（整宽、无圆角） | ❌ | 和米白底互相打架 |

antd-mobile 的 `List` 要加 `mode="card"`：

```tsx
<List mode="card">   {/* ✅ 卡片形态 */}
<List>               {/* ❌ 通栏形态 */}
```

## 圆角与间距

| 项 | 值 | 说明 |
|----|-----|------|
| `borderRadius` | `12` | 通用圆角 |
| Card 圆角 | `16` | 卡片更圆，削弱表格感 |
| 圆形图标按钮 | `50%` | `.icon-btn` |
| 胶囊 / 徽标 | `999` | 标签、Badge |

## 图标规范

| 场景 | 用什么 | 说明 |
|------|--------|------|
| PC 全部 | `@ant-design/icons` | 主库，单色、线宽统一 |
| 移动 · 页面内 | `@ant-design/icons` | 与 PC 同一套，避免认知不一致 |
| antd 覆盖不到 | `lucide-react` | 补充库（已安装），纯线性 stroke 风格 |
| 移动 · 底部 TabBar | 自绘多色 SVG（`public/svg/`） | **唯一例外**：选中态彩色 + 弹跳动效依赖多色图标 |

### lucide-react 使用边界

antd 图标覆盖不全时（锅、厨师帽、家庭关系），用 lucide 补充。三条纪律：

1. **整组替换，不单点混入** —— 一排里只换一个会露馅
2. **线宽固定 `strokeWidth={1.75}`** —— 默认 2 偏粗，1.75 更接近 antd Outline
3. **尺寸同一套**：14 / 16 / 18，不另造档位

❌ 不再引入 `antd-mobile-icons`
❌ 同一屏不混用两套图标表达同一含义

## 写代码的硬规则

1. **不写字面色值** —— 用 CSS 变量或 theme token
2. **同一语义只有一个色值** —— 不允许两种灰并存
3. **改色先改规范** —— 想加新颜色，先在本文的表里加一行
4. **品牌色只有一个来源** —— `theme.ts` 的 token 与 `index.css` 的变量同源

## 两端组件选型

### PC · Ant Design 5

通过 `ConfigProvider` 覆写 Design Token。特有项：`Layout` 顶栏白底高 64；`Menu` 选中底色 `primary-soft`、选中文字 `primary`；Card 圆角 16。

### Mobile · Ant Design Mobile

用在 `MobileTabBar`、菜谱列表、食材库、个人中心等处（`TabBar` / `SearchBar` / `List` / `Card` / `Switch` / `Dialog` / `Toast` / `Empty` / `Badge`）。

- 触屏友好：按手指热区尺寸做的安全区/高度、`PullToRefresh`、`SwipeAction` 手势交互现成
- 交互：底部 TabBar 常驻、搜索框与标签栏吸顶、单列卡片流式

## 分端适配规则

### 设备判定

| 需求 | 工具 | 判定方式 |
|------|------|---------|
| 手机 / 非手机 | `useIsMobile` | 宽度 <768 |
| Pad 竖屏 | `useIsPadPortrait` | 竖屏 + ≥768 |
| 是不是 PC（管理员用） | `isPcDevice()` | UA 级，含 iPadOS 桌面 UA |

> iPad Pro 12.9 竖屏和 iPad 9.7 横屏宽度同为 1024，纯宽度区分不了「竖 3 横 4」，必须方向 + 宽度联合判定。

### 菜单卡片墙列数

| 场景 | 列数 |
|------|------|
| 手机竖屏（<768） | 2 |
| Pad 竖屏 | 3 |
| Pad 横屏 | 4 |
| PC 全屏 / 缩放 | 4 起，随宽度收窄变 3 / 2 |
| PC 竖屏 | 3（命中 Pad 竖屏规则） |

### 手机端锁竖屏

和微信一样，手机不支持横屏：

- PWA：`manifest.orientation = 'portrait'`（安卓加到主屏幕后系统级锁竖屏）
- 浏览器兜底：`LandscapeGuard` 在「手机 + 横屏」时盖全屏毛玻璃遮罩
- 手机判定用 UA，不用宽度（横过来会被误判成 PC）
- iPad / 安卓平板放行，横屏正常用
